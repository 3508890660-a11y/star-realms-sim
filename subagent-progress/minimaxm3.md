# MiniMax M3 · 壁垒重锤（Bastion & Hammer）

## 一、策略名称与选择理由

**策略名：壁垒重锤。**

1v1 的规则我逐条核对过引擎实现后，得到三个决定性的事实：

1. **唯一的胜利条件是把对手的权威打到 0**（`standard` 50 权威，`team2v2` 队伍共享 75 权威）。
2. **对手只要控制任意一座前哨基地（outpost），我就完全无法攻击他的权威**——引擎的 `attackActions` 里 `canAttackPlayer(...) && !teamHasOutpost(opponent.id)` 是一个硬门槛。反过来，**我自己有前哨，就能完全锁死对手对我的权威伤害**，而且这不影响我打他。
3. **基地受到的伤害在回合末清零**（`endTurn` 里 `s.damage = {}`），所以拆墙必须在一个回合内一次打满防御值，半血打墙等于白打。

把这三条合起来看，1v1 的最优解不是无脑对冲血条，而是两段式：

- **壁垒**：用可重复触发的基地引擎（储藏筒仓每回合 +2 权威、贸易站/易货世界/防御中心每回合换权威、战争世界/空间站每回合 +战斗）把自己的权威血线一层层堆高；同时手上有前哨时顺手造一道墙，让对手的直伤通道整个回合对我关闭。对手想打我，必须先把整面墙一次打穿——那一回合他一滴权威伤害都打不出来。
- **重锤**：把一整个回合的战斗资源攒成一次爆发，先把对手的前哨墙一击拆掉，再把剩下的战斗全额灌进他的权威。

所以策略名取「壁垒重锤」：**先筑墙（防守 + 权威引擎），再落锤（爆发拆墙 + 打穿权威）**。这与常见的「抢节奏对拼血条」不同：它承认了前哨墙这个非线性开关，并且主动去利用它。

## 二、核心思路

### 2.1 三种资源的性质完全不同

| 资源 | 回合末是否清零 | 性质 |
|---|---|---|
| 贸易（trade） | **清零** | 当回合必须花掉，否则作废；只有通过购买才能变成牌 |
| 战斗（combat） | **清零** | 当回合必须用掉，否则作废；唯一的伤害来源 |
| 权威（authority） | 不清零 | 血条，只会因为「买来的牌 / 基地产能」而变高，掉了就只能靠伤害换时间 |

由此得到三条硬规则，也是脚本的行为主线：

- **贸易不能攒**：晚花一分钟就等于白扔，所以每回合都要把贸易换成能循环产出的牌。
- **战斗不能省**：战斗是唯一的伤害货币，放着不用等于放弃这回合的伤害。
- **权威要尽量堆**：权威是自己的血条，它不会清零，而且**每点权威等价于「让对手多打 1 点伤害才能杀死我」**，在产能递增的对局里还能多换一回合的产能。

### 2.2 基地是复利，飞船是循环

- **基地（base）**留在场上不消失，主要能力每回合都能再触发一次 → 估值应当是「每回合产能 × 剩余回合数」，而不是一次收益。储藏筒仓（2 贸易，每回合 +2 权威）、战争世界（5 贸易，每回合 +3 战斗且同盟再 +4）都是典型的复利资产。
- **飞船（ship）**回合末进弃牌堆、随后洗回牌库，因此**买一次可以反复打**。脚本给每张买来的牌估「还能打几次」：牌池越大循环越慢，这个系数随牌池规模自动收缩，避免无脑囤牌。
- **购买先进弃牌堆**：所以买来的牌要等 1~2 回合才摸得到，估值时要扣上手延迟。

### 2.3 前哨墙的攻防账

- 对方有墙 ⇒ 我这回合打不到他的权威，战斗只能拿去拆墙；**拆墙必须一击致命**，所以战斗要攒成一次爆发而不是每回合削一点。
- 我方有墙 ⇒ 对方这回合对我零伤害（他的战斗全砸在墙上），墙的防御值就是替我挡下的伤害量。
- 因此脚本对前哨墙按 `min(防御值, 对手每回合战斗) × 0.85` 计价：既奖励「顺带能打的墙」，也避免为纯墙牌（战斗空间站）浪费贸易。

### 2.4 估值统一到「战斗等价点」

脚本不读引擎内部状态，只用 `view` + `legalActions`，所以自带一份 94 张卡的独立知识表（费用 / 防御 / 前哨 / 主要 / 同盟 / 可选 / 销毁能力），并把所有收益折算成同一个单位——**战斗等价点（CP）**：1 点战斗 = 1 CP，1 点贸易 = 1 CP，1 点权威 = 1 CP（先血模式打折为 0.5），1 张抽牌 = 1.15 CP。前哨墙、抽牌、弃牌逼迫、免费拿牌等非线性效果另设经验系数。

## 三、动作优先级

脚本对每个候选动作打分，然后**按分层强制排序**，而不是单纯取最高分。分层是这套打法能落地的原因：

| 层 | 顺序 | 内容 | 理由 |
|---|---|---|---|
| 0 | **致命攻击** | 能直接结束对局的一击 | 立刻结算 |
| 1 | **出牌（play）** | 手牌逐张打出 | 出牌不花钱，是当回合唯一的免费产能；且先出牌才能触发同盟、才能让 `toHandIfFaction` 的牌（警戒信标 / 殖民播种舰 / 等离子喷口 / 皇帝无畏舰）在购买时直接进手 |
| 2 | **发动能力（ability）** | 基地主要 / 同盟 / 可选 / 销毁 | 资源是白给的；分层保证引擎每回合都会被触发，也保证「战斗荚舱：可选能力 → 交易行」这类干扰对手的动作不会被漏掉 |
| 3 | **购买（buy）** | 交易行与探索者 | 贸易会清零，晚花就作废；但要排在出牌之后，才能吃到手牌带来的贸易与阵营加成 |
| 4 | **攻击（attack）** | 打玩家权威 / 拆基地 | 必须排在最后，否则会把本回合后面攒出来的战斗白白浪费掉 |
| 5 | **预留（transfer）** | 2V2 给队友 | 只在自用不完时给队友 |
| 6 | **结束回合** | — | 兜底 |

关键细节：

- **攻击永远选最大伤害**，除非那一击会「打完反而让对手赢」（先血模式：击倒者右侧的邻座获胜，若那不是我则这击不打）。
- **打不满防御值的基地不碰**（伤害回合末清零，打一半等于零），脚本给这类攻击负分，避免把战斗浪费在无效削血上。
- **先血模式**把权威产出的估值砍半：胜负只看谁先击倒，血线不保命，应该all-in伤害而不是堆防御。
- **未知动作类型**统一降级到最低优先级返回，绝不拼接自造动作，永远从 `legalActions` 里原样取对象。

## 四、模式与扩展适配

**五种模式**

| 模式 | 适配要点 |
|---|---|
| `standard` | 基准。两段式打法完全展开：引擎 + 前哨墙 + 爆发拆墙 |
| `ffa` | 多人混战，目标选取按「谁最接近被淘汰」倾斜；前哨墙仍可用于挡直伤，但价值略降（对手可能转头打别人） |
| `hunter` | 只能攻击左手边玩家；脚本沿用引擎同向的邻座定义选目标，基地可打左右邻座。伤害要集中在左手边那位身上 |
| `firstBlood` | 胜负只看「谁先击倒、且击倒对象右侧邻座是自己」。脚本会在能一击击倒左手边邻座时立刻兑现（该击会让别人赢则拒绝），并把权威估值降到 0.5，避免用防御换无用血线 |
| `team2v2` | 队伍共享 75 权威：我的权威增益等于给队伍加血，我的伤害直接扣敌方队伍血条；墙要按「全队」判定；贸易/战斗自用不完时以 `transfer` 预留给队友（预留会在队友回合开始时到账） |

**扩展牌包（core / colonyWars / events 任意组合）**

- 核心盒与殖民战争的 94 张交易牌全部录入知识表，**卡池变大不影响策略本身**，只是把「每回合产能」的来源换了一批（例如储藏筒仓、贸易运输舰、和平卫士、隐匿尖塔、焚化炉都是殖民战争的牌）。
- `events` 牌会把事件插进交易行，随机性变高但不影响决策框架；四种需要抉择的事件全部单独处理（见下）。
- 只有 `core` 牌包时，权威引擎主要来自贸易站、易货世界、防御中心、中央总署、忠诚殖民地；只有 `colonyWars` 时则多了储藏筒仓（每回合 +2 权威，2 贸易）这类更硬的引擎——脚本会自动按当时可见的牌池重新估值。

## 五、事件与 2V2

**事件抉择（eventChoice）**

| 事件 | 规则要点 | 脚本的选择 |
|---|---|---|
| 黑洞 | 弃 1 张掉 4 权威，弃 2 张不掉 | 比较「弃牌的牌力损失」与「掉权威（且不低于 1）」，取小者；通常弃掉最不值钱的 2 张 |
| 轨道轰击 | 摧毁自己一座基地，或失去 6 权威 | 比较「摧毁该基地损失的剩余产能」与「6 权威」，取小者；不会无脑拆掉权威引擎 |
| 彗星 | 可弃手牌/弃牌堆至多两张 | 销毁毫无收益，**一张都不销毁** |
| 跃迁 | 抽 3 张，选 2 张放回牌库顶 | 把 3 张里最不值钱的 2 张放回牌库顶，把好牌留在手里 |

其余事件（银河峰会、类星体、超新星、贸易任务）由引擎即时结算，脚本无需选择。

**其他待决选择**

- 强制弃牌 / 强制销毁：按「牌的剩余价值」排序，丢掉最不值钱的那张（探索者因为销毁后能回到供应池，估值略低于其循环收益，因此不会被当成垃圾丢掉）。
- 指定弃牌目标：挑手牌最多、血线最高的对手，逼他弃掉关键牌。

**2V2**

- 权威是队伍共享的，脚本对「敌方队伍血条」而非个人血条做 lethal 判定，一击清零即获胜。
- 前哨墙按**全队**判定：只要敌方任一队员有前哨，我就打不到队伍权威，必须先整队拆墙。
- 资源预留：贸易只有在我自己花不掉（超过当前交易行最低可负担价）时才转给队友；战斗在没有任何合法攻击目标时才转给队友，避免白白浪费。

## 六、取舍与已知弱点

**已知弱点**

1. **前哨墙可能把局面拖成长局**：双方都筑墙时，谁都打不到对方的权威，比赛会拖长（自检中最长 47 回合、约 500 动作，远低于引擎 10 万动作上限，但没有上限风险）。这是本策略最明显的代价。
2. **权威估值是线性的**：实际上一部分权威只有在「势均力敌」时才有价值；如果我方产能明显落后，堆血线只是延长刑期。脚本用「剩余回合数」粗略代理这一效应，没有做真正的双线博弈推演。
3. **估算是贪心的，不是搜索的**：脚本只能看到 `view` 的公开信息与当前合法动作，无法预演对手回应，面对「对手下一回合会拆我的墙」这类反制缺少前瞻。
4. **购买回报依赖循环假设**：「买一次能反复打」的估值假设牌池里凑得齐 5 张好牌；牌池里全是侦察艇时，买入的实际收益会低于估值。
5. **牌表硬编码**：脚本自带 94 张卡的知识表，若日后引擎调整卡牌数值或新增卡牌，需要同步更新这张表（未收录的牌会退化为「近似中性估值」，不会报错，但会变笨）。
6. **不理解对手意图**：在混战里不会预判「某人下一回合要当垫脚石」，也没有针对特定对手的针对性策略。

**为兼容性做的让步**

- 为了保证五模式 × 任意牌包组合都能跑完，脚本刻意不做「只支持标准局」的激进假设：目标选择、邻座方向、队伍血量、事件抉择全部按引擎同一套定义实现。
- 为避免死循环与超时，脚本是纯函数式的单步决策（每次调用只返回一个动作，不做内部循环），复杂度是 O(合法动作数 × 牌表大小)，单次决策耗时在毫秒级。
- 所有对外接口只读 `view`、只读 `legalActions`，不排序原数组、不修改冻结对象、不抛异常（整体包在 try/catch 中，异常时退回 `legalActions[0]`）。

## 三、新增 3V3 模式适配

### hydra3（三头龙 · 6 人两队各 3 人）
- **权威**：全队共享 100 权威。血线读 `view.players[].authority`（引擎在共享权威模式下会把队伍权威同步到每个队员，两者恒等），只要把任一敌方队员的权威打到 0，即整队出局。
- **前哨保护是整队级的**：与引擎 `teamHasOutpost()` 一致——只要同队**任意一人**有前哨，整队都受保护，敌方「打玩家」的动作会整体消失。因此脚本按整队口径统计前哨墙，并在「看不到打人动作」时判定为「被墙封锁」，而不是误判为无路可走。
- **整队轮流**：同队按座位升序连续行动（0→2→4→1→3→5）。脚本据此识别「下一位行动的队友」，把战斗/贸易转给下一位队友时按「当回合即可到账」估值（队友回合开始时 `beginTurn()` 把预留加进资源池）。
- **伤害队末才清零**：队友造成的基地伤害会保留到全队行动结束 → 团队模式下「差一点点打不穿墙」的部分伤害计为有效进度；并用「我的战斗 + 队友手牌战斗预估」作为全队拆墙预算。
- **起手牌**：偶数座位 3 张、奇数座位 5 张，不再按「座位 0 特殊」处理。

### emperor（大将战 · 每队 1 大将 60 权威 + 2 提督 50 权威）
- **胜负条件是大将被击败**，不是把所有人权威清零：脚本对「打敌方大将」给最高权重（推进唯一胜路），对「打提督」只给较低权重（因为提督有 50 权威血线，必须打到 0 才阵亡，而阵亡只是解锁敌方大将的通道）。
- **血线读个人权威**，`view.teams[].authority` 在该模式恒为 0，已彻底不再用于斩杀判断。
- **可打谁完全以 `legalActions` 为准**：大将可打任何敌方玩家与基地；提督只能打对位提督及其基地，对位提督阵亡后才解锁敌方大将——这些由引擎过滤，脚本不再自己推导对位表，避免按座位 +1 推错。
- **`moveCard`（新）**：花 1 贸易把弃牌堆的一张牌交给队内相邻队友（环形相邻）。已识别并给出保守估值——弃牌堆里的牌对队友价值有限，只有在贸易明显盈余时才作为「结束回合前的兜底动作」使用，绝不抢占建引擎、买牌、拆墙等正经动作。
- **起手牌**同样按队发放（偶数 3 张、奇数 5 张）。

## 四、新牌包与新动作适配

### 新牌包（frontiers / crisisFleets / crisisBases）
- 三个新牌包共 55 种卡面全部补进卡牌表（含 `doubleAlly` 双同盟、`gainCostCombat` 按费用得战斗、`combatIfScrap` 销毁才得战斗、`acquireCheapFree` 免费低价获取、`scrapRowGainCostCombat` 销毁交易行按费用得战斗、`minScrap` 至多 N 张等新效果）。
- **估值主路径已从「查表」改成「读卡面」**：`view.cards[uid]` 的 `cost` / `defense` / `outpost` / `type` / `faction` 直接使用，`text` 由解析器拆成主要能力 / 同盟 / 双同盟 / 可选 / 销毁 / 二选一分支六类效果；查表只用来把分支与数值算得更准。写死的价值表因此从「唯一依据」降级为「加成项」。
- 因此「只开 frontiers」「只开 crisisFleets」「只开 crisisBases」「全开」等任意组合都能正常估值，脚本没有任何一处依赖牌包名或固定交易行卡名。

### 新动作与新字段
| 动作/字段 | 适配 |
|---|---|
| `{type:'ability', ability:'ally', double:true}` | 双同盟：用**双同盟专属效果**估值（与普通同盟效果数值不同，例如同一张牌同盟给 1 贸易、双同盟给 4 战斗 + 4 权威），不再误用普通同盟数值；引擎内部以 `ally#2` 记账，脚本不需要关心。 |
| `{type:'moveCard', cardId, targetId}` | 大将战新动作，已识别 + 保守估值 + 安全兜底。 |
| `play` 的 `choice` | 二选一分支逐个估值后择优（`acquireFreeMax` 分支还会带 `row`，一并计算免费拿牌的价值）。 |
| `play` / `ability` 的 `row`、`rows` | 区分「免费/低价从交易行拿牌」「销毁交易行换战斗」「销毁交易行换权威」等不同语义，分别估值。 |
| `ability` 的 `targets` | 销毁自身手牌/弃牌堆时，按被销毁牌的剩余价值扣减；`minScrap`（至多 N 张）允许少选，估值随实际张数变化。 |
| `ability` 的 `targetId` | 摧毁基地类能力按「断产能 + 拆墙打开权威通道」计价；`targetId: null`（只销毁自身）单独处理。 |
| `ability` 的 `resource` | `depot` 的「弃牌换 2 贸易 / 2 战斗」按 `resource` 分别计价。 |
| `{type:'eventChoice', ...}` | 黑洞 / 轨道轰击 / 彗星 / 跃迁四个事件沿用上一版口径；新增**未知事件兜底**：在所有分支里挑「代价最小」的一个（弃牌损失 + 权威损失 + 基地损失统一比较）。 |
| `discard` / `selectScrap` / `targetDiscard` | 强制弃牌与强制销毁选最不值钱的牌；指定弃牌目标优先手牌最多、权威最高者（大将战里优先敌方大将）。 |
| 任何未知 `type` | 落到最低优先级评分，但仍是 `legalActions` 中的原样对象引用，不会抛异常、不会死循环。 |

## 五、团队回合结构变化带来的估值调整

1. **整队轮流 → 转移资源要按「到账时点」估值**
   旧脚本把 `transfer` 当作「下个回合才能用」的资源搬运，贸易只在「自己花不掉」时才转、战斗只在「完全没有攻击动作」时才转。新版按引擎 `nextTeamTurn()` 算出**紧接着行动的队友**（同队座位升序的下一位）：转给这位队友的贸易/战斗在他回合开始时立即到账，价值上浮；若自己也能打，则只有「全队打不穿墙、需要接力」时才值得转交（这是团队模式拆墙的新路径）。

2. **队末才清算 → 部分伤害不再算浪费**
   非团队模式下基地伤害回合末清零，打不穿墙就是白费（脚本据此把「打不穿」判为负分，避免空放战斗）。团队模式下伤害保留到队末，队友可以接着打同一座墙，于是脚本把「差一点点打穿」的部分伤害计为有效进度（可达则按 0.6/点计，否则按 0.15/点计），并新增「全队战斗预算」= 我的战斗 + 队友手牌战斗预估，用于判断这道墙本轮能不能被全队接力拆掉。

3. **前哨保护是队伍级 → 墙的厚度按整队统计**
   `team2v2` / `hydra3` 下「整队有一座前哨即全队受保护」，脚本统计敌方前哨墙时按整队汇总防御值，并按引擎口径区分「共享权威的队伍模式（整队级）」与「大将战/混战/猎杀（仅本人级）」，避免把墙算薄或算厚。

4. **起手牌按队发放 → 牌池与节奏估算**
   团队模式偶数座位 3 张、奇数座位 5 张（旧版 2v2 走的是混战分支，会算出 [3,4,5,5]）。脚本据此重算牌池大小与「一张买来的牌还能被打几次」的复用系数，避免在团队模式里高估续航、少估手牌压力。

5. **战斗资源仍按人清零，伤害按队清零**
   引擎在队内换人时只清本人本回合的贸易/战斗/触发标记（不弃手、不补牌、不清基地伤害），全队行动完才统一弃手、飞船进弃牌堆、补 5 张并清空伤害。脚本据此区分两种「时间尺度」：**资源看自己这一回合，伤害看整队这一轮**——估「这一击能不能拆墙」用个人战斗，估「这道墙这一轮会不会被拆掉」用全队预算。

## 六、取舍与已知弱点

**取舍**
- **写死的卡牌表保留但降级**：表能给出引擎内部的精确分支与数值（例如 `acquireCheapFree` 的 `maxCost`/`toTop`/`toHand`），但为了不让脚本在遇到未来新牌时彻底失灵，估值主路径改成「可见字段 + 卡面 text 解析」，表只做精确化与加成。代价是文本解析对少数花式卡面（条件触发型）会有偏差，遇到这类卡时以查表结果为准。
- **「打不穿就空放」的旧铁律在团队模式被放松**：非团队模式仍然坚决不空放战斗（保持「壁垒重锤」的核心纪律），团队模式则允许用部分伤害换队友接力，因为伤害到队末才清零。
- **目标推导交给引擎**：放弃自己按座位奇偶/对位表算「能打谁」，改为直接读 `legalActions` 的 `attack.targetId`。这牺牲了一点「提前规划」，换来与规则永远一致。
- **`moveCard` 保守处理**：队友弃牌堆里的牌价值有限，因此只在贸易盈余、且没有其它正经动作时才作为兜底使用；宁可少用，也不让它挤掉建引擎与拆墙。

**已知弱点**
- 大将战里「提督 50 权威 → 必须打到 0 才阵亡」这条硬门槛，意味着前期对提督的伤害属于「沉没成本」，脚本已把打提督的权重压低，但仍可能出现「差几点没打死提督」的短期收益波动。
- 卡面文本解析是规则驱动的近似实现，对将来新增的全新效果方言（如新的条件型或复合型效果）可能识别不到；此时该卡会退化为「只按可见字段估值」，价值可能被低估而不出手。
- 共享权威模式（team2v2 / hydra3）里权威是队伍共同血线，脚本按「打任一敌方队员都会掉同一池血」处理，没有做「优先打哪个队员更好」的精细区分（例如逼对方提前弃牌的节奏收益）。
- 交易行永远按 5 个位置处理（当前引擎固定 5 行）；若将来改变行数，脚本会按实际长度遍历，只是估值里对行位置的偏好仍是通用的，不依赖具体行数。
- 未接触任何历史对局结果、胜率、排名或旧报告；本版所有判断只依据 `PROGRAM-UPDATES.md` 与 `engine/*.js` 的实际代码。
