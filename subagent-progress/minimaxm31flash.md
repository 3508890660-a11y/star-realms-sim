# MiniMax M3.1flash · 破垒夺权

## 一、策略名称与选择理由

**策略名：破垒夺权（Breach the Wall, Seize Authority）**

**理由：1v1 的胜负只有一条通道，而这条通道由「前哨基地」这道墙守着——先破墙，再夺权。**

《星域奇航》的血线是权威，权威只能被「战斗」直接扣除。但引擎里有一条决定性的规则：只要对手还占着任意一座**前哨基地**，他的权威就扣不动、他的普通基地也打不到（前哨是双向护盾——我方有前哨时，对手同样无法直接攻击我方权威）。这意味着：

- **铺得多快不重要**。基地数量决定的是长线产出，不是能不能赢；对局真正结束的那一刻，靠的一定是直伤权威。
- **墙不破，伤害就是零**。对手一座前哨不倒，你的战斗就只能在墙外打转，永远换不来权威。
- **墙是双向的**。你自己不立前哨，对手拆你基地时你同样无从还手。

因此我把打法拆成两个明确的动作序列：**破垒**（单回合打光防御值，拆掉对方前哨，打开直伤通道）与**夺权**（把每回合必定清零的战斗与贸易全额兑现成权威伤害），并用自己的一座前哨为「破垒」争取时间。这就是策略名的由来。

引擎还有两条约束决定了策略的节奏：**`endTurn` 会把 `player.trade` 与 `player.combat` 清零，`s.damage` 也一并清空**。所以贸易和战斗必须当回合花掉，基地伤害不跨回合保留——**拆前哨必须单回合凑够它的防御值**，这要求牌库里有稳定的战斗来源，而不是靠运气抽到一张大牌。

## 二、核心思路

脚本把整个局面折算成一套统一的内部点数（VP），1 VP ≈ 1 点权威伤害，因为权威伤害是唯一的胜负货币。

**牌面估值。** 手工构造 `CARD_DB`，把基础盒与殖民战争共 91 张牌的主要能力、同盟能力、销毁能力、可选能力与「选择：」两支效果全部映射成结构化数值（贸易 / 战斗 / 权威 / 抽牌 / 迫使对手弃牌 / 摧毁基地 / 免费获得 / 弃牌换资源 / 条件抽牌 / 立即入手 等）。这样任何牌包组合都用同一套估值，不依赖运行时反射。

**四组关键折算率：**

| 资源 | 折算 | 理由 |
|---|---|---|
| 战斗 | 通道打开 1.0 VP / 通道堵死 0.6 VP | 战斗只有变成权威伤害才算数；墙没破时战斗只能砸墙，值六成 |
| 权威 | 0.3 ~ 1.35 VP，按赛跑差值算 | 权威就是自己的血线。落后时每点血线都值钱（接近 1.35），领先时血线溢出价值低（接近 0.3） |
| 贸易 | 1.4 VP | 会清零的货币，只能当回合花，所以比战斗更看重「现在能不能花出去」 |
| 抽牌 | 2.5 VP / 迫使弃牌 2.6 VP | 过牌是唯一的复利来源，权重刻意高于单次战斗 |

**牌型系数。** 飞船打出后进弃牌堆（`endTurn` 里 ships → discard），不会自动回手，所以飞船的再利用率只给 1.15；基地留在场上、每回合可重复发动主要能力，所以基地按「每回合产出 × 剩余回合 × 0.5 折现」计价。这个系数是整套估值里最敏感的一个旋钮：飞船循环系数早期误设为 1.7，结果「出牌」的价值永远压过「攻击」，脚本只会攒牌不还手。

**前哨的双向估值。** 自家前哨的价值 = `4 + 1.6×防御值 + 2.2×对手每回合战斗量`，且已有前哨时后续前哨只按 0.2 折算——第一座是护盾，第二座几乎无用（对方只需拆掉任意一座就重新堵死）。敌方前哨的价值则拆成两段：断掉对方长线产出 + **打开通道的翻盘奖励**。后者是整套估值的重头：清空对方全部前哨时额外给 `16 × 队伍系数 + 对方血线 × 0.3`。

**护盾归属组。** 这是 2V2 的关键差异。引擎的 `teamHasOutpost` 在 2V2 下按**整队**判定（一个队友有前哨，全队都受保护），其他模式按**单个玩家**判定。因此「还剩几座前哨要拆」必须按护盾归属组来数，不能按个人来数——按个人算会让「拆掉最后一座」的开门奖励永远拿不到。

## 三、动作优先级

脚本不写死固定顺序，而是**对 `legalActions` 里的每个动作逐一打分，取最高分**；同分时用引擎注入的 `random` 打破，保证行为可复现又不呆板。所有评分共享同一套 VP 尺度，所以优先级是估值算出来的结果，而不是手写规则表。

**第一档 · 致命一击。** 对玩家的攻击若 `amount ≥ 目标血线` 直接给 +1000，等同必胜。这一档在所有模式里都压过其余任何动作。

**第二档 · 破垒。** 攻击敌方基地 / 用能力摧毁敌方基地。拆掉对方**最后一座前哨**时给 `16 × 队伍系数 + 对方血线 × 0.3`，是全局最高的一次性收益——它把「之后每一回合的直伤」全部解锁。2V2 下按剩余前哨数折算进度（`32 / 剩余数`），保证「还差几座」的推进感不会中途塌掉。

关键约束：**基地伤害回合末清零**，所以拆基地必须当回合打死。评分据此分三档——当回合打得死给全额收益；打得死但当前战斗不够、但手牌里还能凑出剩余伤害给 0.7 倍（值得为它继续攒战斗）；完全打不死只给 0.05（基本等于不做）。这条规则直接阻止了「半伤打在墙上白送」的浪费。

**第三档 · 夺权。** 攻击玩家，1 点伤害 = 1 VP。1v1 下这是最纯粹的胜负货币。

**第四档 · 出牌与发动能力。** 打出一张牌 = 牌面效果估值 × 牌型系数。飞船额外叠乘「舰队总部 / 指挥中心」给的额外战斗，基地额外计入每回合产出、前哨护盾价值、`allAlly` / `fleetHQ` / `copyBase` 等标签加成。发动能力时，销毁己方牌会扣掉这张牌的净价值（永久损失），可选的「销毁己方牌」只有在喂给焚化炉（每销毁一张换战斗）时才划算。

**第五档 · 购买。** 净收益 = 牌的价值 − 费用折算的贸易。买入的牌约 2 回合后回到手牌，所以按剩余回合折价；能立即入手的牌（`nextAcquireToHand` 或同阵营条件）额外加权。探索者是 2 贸易换 2 贸易加一个可销毁的 2 战斗壳，净收益极低，优先级被压到接近兜底。

**兜底 · 结束回合。** 只有当所有动作的得分都 ≤ 0.05 时才结束回合，主动避免白白丢掉本回合的战斗与贸易。

## 四、模式与扩展适配

**standard（1v1）**：策略主场。前哨墙是唯一的结构性门槛，脚本的核心价值全部体现在「拆墙 → 直伤」的节奏上。40 局自对弈验证：座位 0 胜 22、座位 1 胜 18、无未结束局，回合数中位 32。20 局行为采样确认策略确实在执行：立起自己的前哨 57 次、拆掉敌方前哨 25 次、攻击玩家 816 次（其中致命 20 次）。

**ffa（3–4 人）**：可攻击任意对手，所以「拆墙」的收益从个体博弈变成公共收益——清掉某人的前哨只对那一个人解锁直伤。脚本因此在补刀逻辑上做了区分：优先集火血线最低的对手（`hp ≤ 全场最低` 时加权），而不是无差别地打最近的墙。

**hunter（3–4 人）**：只能攻击左手边玩家，但基地可打左右邻家。所以「破垒」的收益与「夺权」的收益来源不同——墙拆在右手邻家、直接伤害打左手邻家，两者必须分别估值，不能合并。脚本对基地目标一律用 `canTargetBase` 允许的集合来评分，天然覆盖这个分离。

**firstBlood（3–4 人）**：首位败北时，其**右手边玩家**立即获胜（即引擎的 `nextAlive(X, -1)`）。这条规则让「打谁」变成一个会直接决定胜负的选择：击杀左手邻家＝自己直接获胜；击杀其它任何玩家＝**对手直接获胜**。因此致命一击的评分是双向的——满足条件给 +1000，不满足给 **−1000**（这一刀直接送对手赢），而不是给一个正的淘汰分。

**team2v2（4 人）**：座位 1/3 与 2/4 组队，共享 75 权威。这是与 1v1 结构差异最大的模式，三处专门适配：

1. **前哨是全队共享护盾**。护盾归属组按整队计算，拆墙收益的队伍系数翻倍（`32 / 剩余数`）。
2. **权威是队伍共享的**。`view.teams` 里的队伍权威才是真正的血线，攻击任何敌方队员都扣同一管血，所以「集火」在 2V2 里没有意义，评分只看能不能一口气打穿队伍血线。
3. **`transfer` 资源预留**。队友预留的资源在队友回合开始时到账（`beginTurn` 把 `reserve` 并入 `trade` / `combat`），而我的资源回合末就清零——所以在用不完时预留是有价值的。但必须满足两个条件才给正分：队友确实缺这个资源，且**这笔资源能真正兑现**（贸易要有买得起的牌、战斗要有打得开的通道）。早期版本固定给 4.48 VP，结果 2500 步里发生 1213 次转账、只有 55 次玩家攻击，两队互锁不出结果；修正后转账降到 555 次、玩家攻击升到 11335 次。

**扩展包组合。** `core` / `colonyWars` / `events` 任意组合全兼容，因为估值完全来自手工表 `CARD_DB` 与引擎返回的 `view.cards`，不依赖运行时反射或牌库顺序。5 种牌包组合 × 8 种模式人数配置 × 每组 4 局共 160 局全部正常结束。

## 五、事件与 2V2

**事件（`events` 牌包）。** 事件走 `pending.kind` 分派，四个可能需要决策的事件各自单独估值：

| 事件 | 决策 | 评分依据 |
|---|---|---|
| `blackHole` | 弃 0–2 张牌 | 每少弃一张掉 4 权威；弃进弃牌堆可回收，代价按「弃牌价值」而非「销毁价值」计，并给一个「少弃一张」的收益项 |
| `bombardment` | 付 6 权威 / 摧毁自己一座基地 | 付费按实际掉血量（不会低于 1）折算；摧毁自己基地按「该基地未来产出 × 2.5 + 前哨护盾折价」计损失 |
| `comet` | 销毁自己 0–2 张牌（可来自手牌或弃牌堆） | 默认一张都不销毁；只有能喂给焚化炉换战斗时才值得销毁 |
| `warpJump` | 抽 3 张，把 2 张放回牌库顶 | 留下的那张取价值最高者；放回的两张按「两个候选里较差的」折价 |

另外 `galacticSummit` / `quasar` / `supernova` / `tradeMission` 属立即结算事件，不产生待决选择，脚本无需介入。

**强制待决（`pending` 非事件类型）。** `discard`（弃牌）与 `selectScrap`（销毁）都取「代价最小的那张」：弃牌只损失本回合节奏（`max(0.4, 每回合战斗 × 0.6)`），销毁是永久损失（按牌的净价值计）。`targetDiscard`（指定对手弃牌）挑手牌最多的对手。

**2V2 的额外处理。** 除了上文三处模式适配，2V2 还有两条规则性细节：

- **队伍血线**。`view.teams[].authority` 才是真实血线，`view.players[].authority` 只是同步过去的镜像。脚本的 `targetInfo` 在 2V2 下取队伍权威，击杀判定也对齐整队归零。
- **同队不互害**。`opponents` 排除了同队成员，队友的牌不会被误判成可拆目标；`myOutpostCount` 则把队友的前哨算进来（护盾共享）。

## 六、取舍与已知弱点

**已知弱点：**

1. **墙没拆开时价值估算是钝的。** 战斗在通道堵死时一律折成 0.6 VP，不区分「我这一手能拆掉最后一座墙」与「完全打不动墙」。虽然拆墙有单独的 +16 翻盘奖励兜底，但中局可能出现「明明差 1 点战斗就能开墙，却按 0.6 VP 折价而选择了别的动作」的偏差。

2. **拆墙需要单回合凑够防御值，这是硬门槛。** 前哨防御值 4–6，而战斗回合末清零，所以「攒两回合再打」在引擎层就不成立。牌库里战斗来源断档的回合，脚本会眼睁睁看着这一回合打不出伤害，选择退而求其次去打玩家或买牌。策略的上限因此被牌库的战斗稳定性直接限制，而不是被决策质量限制。

3. **前哨是双刃剑。** 自家前哨挡着对手的直伤，但同时**也替对手挡着对其他玩家的直伤**（在 ffa / hunter 里这是负收益）。脚本的 `myOutpostCount > 0 → 0.2 折算` 只压制了「第二座前哨」，没有按模式区分「第一座前哨在混战里是否值得立」。在 ffa 里前哨的性价比低于 1v1，但脚本给的是同一套估值。

4. **卡牌效果表是手工维护的。** `CARD_DB` 覆盖了当前基础盒 + 殖民战争的 91 张牌，但**新增牌若未补表，`db` 会是 `null`**——此时 `scorePlay` 退化为常数 1、`effectVP` 返回 0，脚本会把这张牌当成平庸牌处理，不会报错但也不会正确估值。当前两种牌包组合已全覆盖。

5. **没有多步搜索。** 评分是单步贪心 + 静态估值，不做「这一回合先攒战斗、下一回合开墙」的规划，只能靠 `reachCombat`（手牌里还能凑出的战斗量）粗略表达「这一手是否值得为补刀而继续」。对手会怎么应对、对方手里有没有能反开我墙的牌，都不进入估值。

6. **2V2 的转账价值仍有简化。** 「队友缺资源」用「队友当前资源 + 预留 < 3」估算，没建模「队友自己这回合能不能赚到」和「这笔资源是否来得及在对手行动前兑现」。多次转账仍可能浪费，但已从 1213 次降到 555 次，且不再压制攻击。

**取舍说明：**

- **用统一 VP 尺度换取可解释性**，代价是不同资源之间的换算率必然粗糙。抽牌给 2.5、战斗给 1.0、贸易给 1.4，这些数字是按 1v1 的实际节奏手调的，换到 ffa 或 2V2 并不最优。
- **选择手工卡表而非解析规则文本**，代价是新增牌需要维护，好处是估值快（单次决策最大 5ms）、行为稳定可复现、不受文本改写影响。
- **选择「逐动作打分」而非分层规则表**，代价是优先级不够生硬直观，好处是任何模式、任何牌包组合都自动继承同一套逻辑，不需要为每种模式写分支。
- **不修改 `view` / `legalActions`**，全部决策只读；同分用引擎提供的 `random` 打破，因此既不违反深冻结约束，也不会因为遍历顺序而在同分动作里产生系统性偏袒。
