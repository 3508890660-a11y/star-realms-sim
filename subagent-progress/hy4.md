自选策略：薄牌护城河

## 一、策略名称与选择理由

**薄牌护城河（Lean Deck Rampart）**。

1v1 基础盒里，权威初始 50、战斗在回合末清零、权威却永久累加且没有上限，而每销毁一张起始废牌（侦察艇 / 毒蛇战机）都会让后续每一次洗牌的好牌密度提高——这是可累积的复利。由此判断：一次性堆战斗的快攻并非最优，因为对手只需前哨挡一回合、或用贸易联邦的权威增益回血，爆发就会被吸收，随后被越来越薄、越来越强的牌组反打。更稳的赢法是先建立两条「护城河」——用压缩与高性价比购牌把牌组质量拉开，用权威增益把有效血线拉到对手难以击穿——只在出现明确斩杀窗口或自身血线告急时才切换攻防。这就是「薄牌」与「护城河」的由来，战斗只作为临界点的收割手段，而非主线。

## 二、核心思路

采用**无状态的局面评估 + 逐动作打分**：每次决策遍历 `legalActions`，给每个动作算一个实数分数，取最高分那一个并**原样返回该对象引用**，不对数组排序、不修改 `view` 或动作对象。动作合法性完全交给引擎，脚本只做「选哪个」。

关键约束是 `view.cards[uid]` 只暴露 `cost / type / faction / factions / outpost / defense / text` 等描述字段，没有结构化的主要 / 同盟 / 销毁效果数值。因此卡牌估值做成**数据驱动**：以 `cost` 为主强度指标，叠加 `type`（基地持续价值）、`outpost` / `defense`（防守）、`faction` / `factions`（阵营协同），再用轻量正则从中文 `text` 提取「数字 + 贸易 / 战斗 / 权威 / 抽牌」的量级作为辅助修正；不硬编码任何单卡数值，故核心盒、殖民战争、事件包的任意组合都能直接评分。

局面层计算四个系数：

- `guard`：自身血线越低越高，放大权威增益与前哨价值；
- `aggro`：存在可致死攻击或对手进入可斩区间时拉满，否则保持低位（不鼓励无脑打脸）；
- `greed`：安全且无斩杀窗口时最高，驱动压缩与购牌，危险 / 斩杀期压低；
- `progress`：本回合已打出手牌占比，用来把 `buy` 与「非致死攻击」压后，保证先把能产资源 / 触发同盟的牌打完，再买牌、再分配战斗，最大化单回合产出。

## 三、动作优先级

分数绝对值形成自然的优先级：

1. **斩杀（最高档）**：`attack` 到玩家且 `amount >= 目标权威` 直接给最高分，并偏好「刚好致死」的 `amount` 以留战斗给其他目标；这是唯一无条件抢先的动作。
2. **打牌与能力**：`play` 给较高基础分（手牌回合末会被弃掉，打出来换资源总是正收益），叠加贸易 / 战斗 / 权威 / 抽牌的即时产出、同盟触发、基地上场、复制、以及「免费获得交易行牌」的加成；`ability` 按种类细分——`ally`（同盟，免费额外价值）与 `primary`（基地主要能力）给正分，`optional` 的销毁手牌只在目标为废牌时给正分、含强牌则给负分（宁可不做），`destroyBase` / `scrapRow` 给中高分，`scrap` 视为「压缩 + 换资源」给正分（基地略减分）。
3. **购牌**：`buy` 用 `cardValue × greed × progress` 评分，并对我方已有同阵营牌数加成，鼓励集中 1–2 个阵营触发同盟；探索者仅在贸易窘迫时给中等分。
4. **攻击与预留**：非致死 `attack` 到玩家按 `aggro` 加权并乘 `progress`；拆基地按费用 / 防御估值，**前哨额外加权**（拆掉才能打人）；`transfer` 给低正分，只在没有更好动作时把回合末会清零的资源转给队友。
5. **受迫选择**：`discard` / `selectScrap` 一律弃 / 销毁价值最低的牌（正好顺手压缩废牌）；`targetDiscard` 选手牌最多、威胁最大的对手。
6. **收尾**：`endTurn` 为 0 分基准；有害动作（如销毁强牌）为负分，会被 `endTurn` 压过；**任何未知动作**返回 −1 分的安全兜底，仍从 `legalActions` 中返回对象，不抛异常、不拼造动作。

## 四、模式与扩展适配

五种模式与三种牌包的任意组合共用同一套逻辑，适配来自两条设计决定：

- **只在 `legalActions` 内选择**：动作由引擎按当前模式 / 规则生成，脚本原样返回其一，因此 `hunter` / `firstBlood` 的攻击目标限制、`ffa` 的多对手、`team2v2` 的队伍规则、`events` 的待决事件都自动合法，无需在脚本里复刻模式规则。
- **估值不依赖具体卡牌清单**：读 `view.cards` 的描述字段与 `view.tradeRow`，因此 `core` + `colonyWars` 混洗、`events` 洗入牌库都无需改动；`view.eventCardsRemaining` / `view.expansions` 不参与买牌决策（事件牌翻出即结算，不会停留在交易行）。

多对手场景用「存活对手最低权威」和遍历 `a.targetId` 处理斩杀与火力集中；`firstBlood` 下斩杀更重要、天然被最高档覆盖；`ffa` 的 `targetDiscard` 从候选里选最划算的目标。

## 五、事件与 2V2

事件包触发的 `eventChoice` 按 `eventId` 分别处理：`blackHole` 在「弃牌损失」与「少弃失血」之间取总代价最小（通常弃两张最废的牌）；`comet` 把销毁视为净收益，优先销毁两张废牌；`bombardment` 比较「拆掉最弱基地」与「失 6 权威」的代价，且避免拆前哨；`warpJump` 把价值最低的两张放回牌库顶、把最好的留在手里；其余事件（含未来的未知事件）给中性分兜底。黑洞 / 彗星 / 轰击 / 跃迁之外，`galacticSummit` / `quasar` / `supernova` / `tradeMission` 由引擎即时结算、不产生待决动作，脚本无需干预。

2V2 下：`transfer` 用于把用不完的贸易 / 战斗预留给队友（资源回合末清零，转走优于浪费），且排在自有好动作之后；权威判断直接用 `view.players[i].authority`——引擎已把队伍权威同步到成员；队伍前哨共享与目标合法性由引擎在动作生成时保证；`targetDiscard` 的候选已过滤队友，脚本只需从中挑最有利者。

## 六、取舍与已知弱点

- **无状态**：不使用 `memory`，不做跨回合统计，避免不同模式 / 座位切换时的状态污染；代价是无法学习对手的长期套路。
- **估值近似**：中文 `text` 的正则对「选择…或…」分支会略高估（把两个选项的资源都计入），对中文数字（「两张牌」）不敏感；`cost` 作为主强度指标无法区分「给贸易」还是「给战斗」，只能靠阵营与文本画像间接推断。
- **信息受限**：对手手牌与牌库顺序不可见，弃牌干扰、爆发预警都只能靠血线与手牌数估计，不做对手手牌建模。
- **不做前瞻**：没有搜索、没有蒙特卡洛推演，`guard` 只看自身当前血线，无法预判对手下回合的爆发总量；面对极限快攻，前期压缩的真空期仍有被冲死的风险。
- **协同近似**：`allAlly`（机甲世界）、复制牌（隐匿针舰 / 隐匿尖塔）的多阵营触发只做简化加成，未精确枚举。
- **顺序启发式**：`progress` 假设「先打完手牌再买」在 1v1 里成立（我回合内交易行不会被抢），在少数需要抢购限量好牌的场景下可能略保守。

总体上，这套打法用可审阅的启发式换取零依赖、全模式兼容与稳定的接口行为，把策略重心放在长局复利与临界斩杀，而非单回合爆发。
