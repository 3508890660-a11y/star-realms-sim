# step5preview 设计说明

## 一、策略名称与选择理由

**策略名称：雪球收割（Snowball-Reap）。**

选择理由：基础盒 1v1 的胜负手可以分解为两个乘数——**经济差**（谁能买到更多更好的牌）和**战斗转化效率**（谁能把战斗值稳定兑换成权威伤害）。纯快攻缺后劲，一旦被前哨或权威牌拖住就无牌可打；纯经济缺防御，被连续进攻时雪球还没滚起来就输了。雪球收割取两端：早期用高性价比贸易牌（探索者、贸易荚舱、穿梭机、巡航快艇）把雪球滚大，中期用高战斗效率牌（虫群、机甲、帝国线）把雪球兑换成权威，同时始终保留权威牌作为生命线。全部决策由同一套「等效权威分」驱动，不依赖对局阶段的人工切换。

## 二、核心思路

1. **统一价值评分**：把贸易、战斗、权威、抽牌、免费获得、拆基地等全部效果折算成「等效权威分」（1 贸易≈0.9，1 战斗≈0.85，1 权威≈1.0，抽 1 张≈2.0），每个动作打一个分，每次决策选最高分动作执行；没有超过阈值的动作就结束回合。
2. **内置卡牌效果表**：引擎视图的 `cards[uid]` 只暴露 name/cost/type/faction/defense/outpost/factions/text，不暴露效果结构。脚本按 `cards.js`/`expansions.js` 内置了一份 91 张卡的效果表（仅用于评分，不参与规则计算），因此 `core`/`colonyWars` 任意组合都自动适配。
3. **动态倾斜**：我权威 ≤25 时权威牌升值（保命），对手权威 ≤15 时战斗升值（抢杀）；memory 记录回合开始权威，若本回合权威下降超过 3 判定为被压制，略降打脸权重、提高权威权重。
4. **前哨博弈**：战斗能一击拆掉阻挡前哨时拆（拆完若再无其他前哨，本回合剩余战斗即可打脸）；拆不动时战斗不打（对基地的伤害在回合末清零，打了纯浪费）。
5. **lethal 优先**：打脸致命一击给 1000 分，永远最先执行；`firstBlood` 模式下若致命击杀的赢家不是自己（败者右手边存活者），该击降到 0.1 分宁可空过——先血模式打死别人等于帮第三者获胜。

## 三、动作优先级

按分数从高到低自然形成以下优先级（同分时取先出现者，全部由引擎重新生成的 legalActions 驱动循环，每个能力/手牌/资源单调消耗，保证收敛到 endTurn）：

1. **致命打脸**（1000 分）：standard/ffa/hunter/2v2 无条件执行；firstBlood 校验赢家。
2. **打出卡牌**：飞船 = 即时效果分 + 0.5；基地 = 长期价值折现（早上场早触发同盟、早用主要能力）。隐匿针舰/隐匿尖塔自动选分数最高的复制目标；自由选择效果（patrolMech、blobWorld、parasite 等）按当前局面实时比较各选项。
3. **同盟能力**：已触发即用（折 0.95），免费获得类选交易行最高分目标；焚化炉先执行主要能力（拆牌）再执行同盟（每张换 2 战斗），顺序由预估分保证。
4. **基地主要能力**：brainWorld/machineBase 弃废牌换抽牌，supplyDepot 弃牌换资源（战斗紧迫时选战斗），回收站选回收，全部按「抽牌期望 − 弃牌损失」计算。
5. **购买**：可买牌分高于探索者（3.2）就买最高分行牌，否则买探索者把贸易花光；置牌库顶/入手/阵营入手有额外加成。
6. **拆前哨 / 打脸**：拆得动的前哨（4.5 + 0.4×防御 + 解锁 2.5）优先于普通打脸；非前哨基地拆解分压到 0.6 倍（低于打脸，一般不拆）；打满全部战斗（amount 打满比留残余高 0.5 分）。
7. **资源预留**（仅 2v2）：买完打完把剩余贸易/战斗全额转给队友（0.85~0.9/点）。
8. **结束回合**：所有动作 ≤0.5 分时 endTurn。

## 四、模式与扩展适配

- **模式无关性**：策略主体不含模式分支；模式只影响两处——lethal 的 firstBlood 校验、2v2 的 transfer。ffa/hunter 下对每个可攻击目标分别评分，对手权威越低权重越高（优先削弱最接近淘汰者），同时多人局权威牌天然升值（权威乘数只跟我方权威挂钩，混战中被集火风险由 underPressure 补偿）。
- **扩展无关性**：卡池由引擎决定，效果表按 id 全覆盖 core + colonyWars；events 只新增 eventChoice 待决分支，不影响主流程。`view.expansions`、`eventCardsRemaining` 仅作信息，不参与决策。
- **未知动作兜底**：评分表只认 play/ability/buy/attack/transfer/discard/selectScrap/targetDiscard/eventChoice 九类 + endTurn；未知类型给 -Infinity 不选，全列表无正分动作时返回 endTurn；整个 chooseAction 包在 try/catch 中，异常时回退到「第一个已知类型的非结束动作」，列表为空时返回 `{type:'endTurn'}`。所有返回都是 legalActions 中的原对象引用，不修改冻结视图、不对原数组排序。

## 五、事件与 2V2

- **黑洞**：枚举全部弃牌组合，最小化「权威损失 + 0.7×手牌损失」；权威 ≥9 且没有废牌时才考虑少弃。
- **轨道轰击**：摧毁己方基地的损失 vs 失去 6 权威（实际损失 = min(6, authority−1)）取小；权威 ≤8 时保命加权，多座基地时自动拆最废的那座。
- **彗星**：只销毁低分废牌（拆牌收益 = 1.2 − 0.45×牌分），好牌不拆。
- **跃迁**：抽到的 3 张里把分数最高的 2 张按序放回牌库顶。
- **先血/混战/猎杀**：lethal 判断如第二节；先血模式主动避免「替别人做嫁衣」的击杀。
- **2V2**：transfer 只在打不了脸/买无可买时执行，全额转出；攻击目标是引擎判定的敌队玩家/基地，lethal 按敌队共享权威判断；权威管理比 1v1 更重要（双倍进攻压力），权威乘数不变但 underPressure 补偿照常生效。

## 六、取舍与已知弱点

1. **不做局面搜索**：纯贪心 + 静态价值表，不模拟对手回合。面对需要「留一张牌防事件/防弃牌」的场合只会按长期价值行事，可能拆掉/弃掉对手回合里更有用的牌。
2. **权重是拍的**：0.85/0.9/1.0/2.0 这组折算系数来自经验值而非拟合；遇到极端环境（如大量权威事件的 events 局）可能偏斜。
3. **前哨换血偏保守**：拆不动前哨时直接放弃本回合战斗，不把伤害「垫」上去——这正确利用了回合末清零规则，但也意味着面对「这回合拆一半、下回合补一点」的局没有额外收益。
4. **拆交易行偏保守**：只在「我买不起且费用 ≥4」时拆，不针对对手已知的经济节奏做预判（视图里看不到对手手牌，也无法可靠推断）。
5. **先血多人局偏龟**：误杀会被动放弃致命一击，遇到必须抢击杀的残局可能拖长局数；这是正确性优先的取舍。
6. **复制牌评分近似**：隐匿针舰/尖塔按复制目标的静态分选择，不考虑复制后新触发的同盟连锁，可能错失组合技。

**第 6 条（硬性自检）**：7 模式 × 6 牌包覆盖；未知动作类型走 `scoreUnknown` 低分兜底（引擎对未知 `type` 会直接抛错，因此绝不让它抢在 `endTurn` 前面），异常总兜底 `fallbackAction` 保证返回数组内引用；零依赖；不写冻结对象、不对原数组 `sort`；单次决策最坏 2.4ms（selfcheck 实测），远低于 3000ms。

## 二、新增 3V3 模式适配

**hydra3（三头龙，6 人两队各 3 人，共享 100 权威）**：
- 敌我按 `team` 字段划分；权威是队伍共享的，所以**攻击任一敌人都等效削减对方全队血量**，`amount >= authority` 即按全队出局记 1000 分。
- 前哨保护看对方全队：`scoreAttack` 拆哨时统计对方全队前哨数，拆掉最后一座才给 `outpostUnlock` 解锁分。
- 合击同一座基地：伤害队末才清，`view.damage` 里已有队友打出的伤害会被引擎自动计入 `needed`，脚本据此判断能否一击拆掉；打不掉且队友随后行动时允许先摸。
- 队友间转移贸易/战斗：`transfer` 评分按「下一个行动者是否队友」折价，队末成员不浪费战斗去摸基地。

**emperor（大将战，6 人，1 大将 60 + 2 提督各 50）**：
- 权威在个人身上，`teams[].authority` 为 0，全部读取 `players[i].authority`；`view.emperors` 给出大将座位，斩杀估值只对大将座位给满分。
- 可打谁完全信任 `legalActions` 的 `attack.targetId` / `ability.targetId`，不按座位奇偶或对位表推导（提督对位是「两队提督按队内座位序一一配对」，不是座位 +1）。
- 前哨保护是**个人级**：打某人的脸只看他自己有没有前哨，因此 `faceBlocked` 按敌人个人统计。
- `moveCard`（花 1 贸易把弃牌堆一张牌交给相邻队友）有独立评分，偏废牌清理与给大将供牌，默认低分。
- 提督阵亡不计负分也不冒进：非致命时按普通输出估，致命时记 40 分（高于一切常规动作、低于大将斩杀）。

## 三、新牌包与新动作适配

- **`double:true` 的 ally**：双同盟被视为「一次额外同盟机会」。若卡有 `doubleAlly` 效果（如蜂巢女王、轻巡洋舰、离子站、虫群集群、虫染之月）按该效果评分；未知卡退回普通 `ally` 效果，绝不因字段陌生而抛错。
- **`moveCard`**：见上，`scoreMoveCard` 处理 `{type:'moveCard', cardId, targetId}`，含目标为大将的小加成与废牌判定。
- **带 `choice` 的动作**：`{type:'play', cardId, copy, choice}` 按 `primaryChoice[choice]` 取分支；分支含 `acquireFreeMax` 时还会带 `row`，按该行卡的价值 + 免费获取红利估；无可拿目标时该分支判 0 分。
- **带 `row` / `rows` 的动作**：免费获取（`acquireCheapFree`/`acquireShipFree`/`acquireFreeMax`）、按费用换战斗（`scrapRowGainCostCombat`/`gainCostCombat`）、销毁交易行（`optionalPrimary.scrapRow` 的 `row`/`rows`）都按行内卡的费用与估值打分，并保留「这回合还买得起的高分牌留给 buy」的旧取舍。
- **带 `targets` 的动作**：销毁手牌/弃牌堆（`scrapOwn`/`minScrap`/`zones`）、弃抽（`discardThenDraw`/`depot`/`recycle`）按目标张数折算收益，并按「手牌折 0.8、弃牌堆折 0.25」扣除损失；`depot`  additionally 看 `resource` 与当前贸易/战斗紧迫度。
- **带 `targetId` 的动作**：`destroyBase`（含 `targetId: null`）按目标基地威胁分 + 摧毁红利估；提督/大将攻击与指定同理。
- **未知动作/未知卡**：未知动作 `scoreUnknown` 只给 0.1~0.2 的低分（低于 `endTurn` 优先级），未知卡走 `textFx` 文本解析，双层兜底保证不抛异常、不死循环、不返回非法引用。

## 四、团队回合结构变化带来的估值调整

- **整队轮流**（6 人 `0→2→4→1→3→5`，2v2 `0→2→1→3`）：脚本用「是否存在座位更大且未淘汰的队友」推断下一个行动者是否队友。由此产生两个调整：① `transfer` 给下一个行动的队友价值上浮（资源当回合到账、可立刻买牌或补刀），给已行动过的队友打折；② 团队模式下允许对打不掉的基地「摸一下」——伤害会保留到队末，队友接力即可拆掉。
- **队末才清算**（换人只清本人贸易/战斗/能力标记，不弃手不补牌不清基地伤害）：因此① 队友合击同一座基地是正收益，部分伤害按「威胁分 × 进度比例」打折计分，且优先摸前哨；② 反过来，我是队末时摸一下纯浪费（队末清零），该分支直接关断；③ 非团队模式保持旧口径（回合末清零，打不动就不打）。
- **起手牌按队发放**（偶数座位全队 3 张、奇数座位全队 5 张；2v2 `[3,3,5,5]`、6 人 `[3,3,3,5,5,5]`）：脚本不写死起手结构，但据此加了「手牌 ≤ 2 时抽牌价值 × 1.3」的紧迫加成（`lowHand`），让 3 张起手的座位更早滚经济，契合雪球收割的早期思路。团队模式里前哨的长期价值也上调（`outpost` 权重 × 1.4，全队共享保护；大将战里大将本人 × 1.5，守护胜负手）。

## 五、取舍与已知弱点

1. **textFx 是启发式**：中文卡面解析覆盖常见句式，对冷僻句式（多层条件嵌套、中文数字、以及/或分支）只能近似；未知卡的估值精度低于 FX 表内的卡。缓解手段是 FX 表已覆盖全部 6 牌包 219 张已实现卡，textFx 实际只兜底合成卡/未来新卡。
2. **合击与 transfer 是单向推断**：只根据「座位顺序」推断下一个行动者，不预测队友的手牌与意图；转给队友的资源可能被低效使用，摸基地也可能没人接力。这是不读他人手牌（视图也不给）下的必然近似。
3. **大将战换牌价值估计偏保守**：`moveCard` 多数情况评为负分（1 贸易成本 vs 弃牌堆收益），可能 rarely 使用；若对手提督阵亡后引擎自动向大将移交牌的节奏更重要，本脚本没有专门利用。
4. **斩杀在 ffa/hunter 只按「剩余敌人数」分档**：不评估先杀谁更优（如先杀威胁最大的玩家），混战里可能出现「致胜一击提前打死了较弱对手」的次优选择。
5. **事件待决只认 4 种**（blackHole / bombardment / comet / warpJump），未知事件各选项等价取第一个；`comet` 选择「基本不拆」偏保守，放弃了「拆弃牌堆探索者回补供应堆」这类微小收益。
6. **不做多步搜索**：全部决策是「当前局面一步效用最大化」，没有 lookahead；在需要忍一手、做局的局面（如故意留战斗防对手爆发）会偏贪。
