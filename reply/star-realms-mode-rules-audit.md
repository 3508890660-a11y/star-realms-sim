# 行动顺序与攻击目标：复核报告（2026-11-09）

> 复核对象：大将战（emperor）的「皇帝可打任何人、提督在对位解决前不能打皇帝」，以及团队模式（2V2 / 三头龙 / 大将战）的「整队轮流」。
> 方法：① 构造局面直接检查 `legalActions()`；② 从 `reply/` 正式报告取种子，逐动作重放真实对局。两条路径都不依赖模型自述。

## 结论

**内核规则已解决；此前「看起来还有问题」的来源是文案，不是行为。**

| 检查 | 方式 | 结果 |
|---|---|---|
| 提督只能打对位提督 | 构造 3 种合法大将座位（`[0,1]` / `[2,3]` / `[4,5]`），逐座位枚举攻击目标 | 通过 |
| 对位存活时不能打敌方大将 | 同上，并对每个提督单独断言 | 通过（0 例越位） |
| 对位阵亡后解锁敌方大将 | 淘汰对位提督后重查 | 通过，且对位关系不漂移 |
| 大将可打任何敌方玩家/基地 | 逐座位枚举 | 通过 |
| 队伍模式只打敌方 | 2V2 / 三头龙逐座位枚举 | 通过 |
| 前哨先于玩家/普通基地 | 构造前哨局面 | 通过（2V2/三头龙按整队，大将战按个人） |
| 整队轮流 | 连续 `endTurn`，检查 `activePlayer` 序列 | 通过（`0→2→4→1→3→5` / `0→2→1→3`） |
| 队内不补牌、队末才补 | 每人手牌压到 2 张后连续 `endTurn` | 通过（队内不变，队末本队补到 5） |
| 真实对局重放 | 4 份 3V3 报告各取 2 局，共 8 局 / 4,967 个动作 | 全部一致：确定性、回合顺序、攻击目标 |
| 提督攻击大将的实际案例 | 上述 8 局 | 14 次，全部发生在对位阵亡之后 |

## 证据

### 1. 构造局面

```bash
node tools/probe-attack-targets.mjs
```

输出要点（2026-11-09）：

- `emperors=[0,1]` 提督对位 `2↔3 4↔5`；`[2,3]` 为 `0↔1 4↔5`；`[4,5]` 为 `0↔1 2↔3`。
- 淘汰 3 号后，对位仍是 `2↔3 4↔5`，没有漂移；2 号解锁敌方大将，4 号仍只能打 5 号。
- 行动序列：三头龙/大将战 `0→2→4→1→3→5→0`，2V2 `0→2→1→3→0`。
- 队内换人手牌不变；队末本队补到 5 张。

### 2. 真实对局重放

```bash
node tools/audit-mode-replay.mjs
```

- 重放 8 局（emperor-core/all、hydra3-core/all 各 2 局），共 4,967 个动作。
- 每局胜队、回合数、动作数与报告完全一致（种子确定性成立）。
- 玩家攻击 443 次、基地攻击 58 次、提督攻击大将 14 次；无一次越位或打队友。
- 回合顺序全部为 `0→2→4→1→3→5`（或 `0→2→1→3`）。

示例种子：`mode-3v3-2026-11-08:emperor:core:s1:r1:m1:g1`（703 个动作、70 回合、胜队 0）。

## 为什么之前「看好像还是有问题」

行为是对的，但文字有三处会让人误判：

1. `src/engine/modes.js` 的三头龙模式描述仍写「交替座位」——它原本指两队**座位排布**交替，却很容易被读成**行动顺序**逐座位交替。
2. 自动生成的 3V3 报告只写了「队内座位按局轮换」，没有写「整队轮流」；旧版本（修正前）的报告也还在 `reply/` 里，容易被当成当前结果。
3. 观战台的 3V3 设计说明没有提回合结构。

已修正：

- 模式描述改为「两队座位交替；同队队友连续行动（整队轮流），队末才弃手、补牌、清基地伤害」。
- `mode-tourney-cli.js` / `team-lab-cli.js` 的报告模板新增「回合结构：整队轮流」一行；`reply/` 下 8 份既有报告的 Markdown 已用新模板重生成（JSON 数据未改）。
- README 16.3 与观战台说明同步。

## 仍未改（已知，且不影响本次两项）

- 大将战 1 贸易移牌仍允许任意队友，官方限「相邻队友」。这是**移牌范围**，与行动顺序/攻击目标无关；要改需要先定「相邻」按座位还是按队内序号，未擅自改。
- 大将战前哨保护按**个人**（2V2/三头龙按整队）。这是当前引擎口径，隔离简报曾把 emperor 概括成全队；已在 README 17.6 留痕。若官方确认 emperor 也是全队，需要单独改并重跑。
