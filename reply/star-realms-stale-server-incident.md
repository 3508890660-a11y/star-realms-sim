# 事件复盘：5 号提督开局攻击 0 号大将（2026-11-09）

## 一、结论

规则没有失效，是**你打开的那个服务是旧进程**。

- 出事的服务：PID 1224，监听 `127.0.0.1:4397`，**启动于 2026-11-08 20:41:30**
- 该进程内存里的代码，早于两次规则修复：
  - `8aa15a0` 提督对位改为「两队提督按队内座位序配对」
  - `167cfe2` 团队模式改为「整队轮流」

旧代码用 `opposite = (座位 + 1) % 6` 算对位，大将坐在 0/1 号位时，5 号提督的对位被算成 **0 号大将**，于是开局就能斩首——你看到的那一手，在旧进程里是「合法动作」。

## 二、证据链

### 1. 进程比代码旧

| 项 | 时间 |
|---|---|
| 4397 进程创建时间 | 2026-11-08 20:41:30 |
| `src/engine/modes.js` 最后修改 | 2026-11-09 17:48 |
| `src/engine/engine.js` 最后修改 | 2026-11-08 21:19 |

Node 只在启动时加载模块，之后改文件对已运行进程无效。

### 2. 旧对局的行动顺序是「交替」而非「整队」

直接从该进程的 `/api/replay` 读出动作序列，按座位去重：

```
0 → 1 → 2 → 3 → 4 → 5 → 0
```

这正是修复前的逐座位交替。当前规则应为 `0 → 2 → 4 → 1 → 3 → 5`（第一舰队三人连续行动，再换第二舰队）。

### 3. 那一手确实存在于旧对局历史

`seed = welcome-01`、`mode = emperor`、`emperors = [0,1]`、第 7 回合：

```
#10  P1 → P0   2 点   （1 号是大将，大将打大将是合法的）
#16  P2 → P3   1 点
#30  P4 → P5   1 点
#38  P5 → P0   2 点   ← 问题所在
```

第 38 步时，5 号（第二舰队提督）的对位应是 4 号（第一舰队提督），而 4 号权威 50、仍然存活。按现行规则这一手非法。

### 4. 用当前引擎重放该局，直接被拒绝

```
回放被拒绝： 回放第 6 步座位不一致
```

第 6 步就崩，是因为旧局的交替回合结构在当前规则下根本走不通——连回合顺序都不一致，说明这个进程落后不止一个修复。

## 三、为什么之前没测出来

之前的构造局面探针、真实报告重放、12 份脚本的 84 场对局，**全部在新代码上跑**，当然不会复现旧进程的行为。测试跑在代码上，而你点开的是进程——两者不是一回事。

## 四、本次加固（三层）

### 1. 引擎：`attack()` 增加二次校验

`applyAction()` 本来就会校验动作是否在 `legalActions()` 内，但 `attack()` 自身没有防线。现在补齐：

```js
if (!Number.isInteger(action.amount) || action.amount < 1) throw new Error('攻击伤害必须是正整数');
if (action.amount > player.combat) throw new Error('战斗值不足');
if (action.targetType === 'base') {
  if (!this.canAttackBase(player.id, card.owner, uid)) throw new Error('该基地当前不可攻击');
} else {
  if (!canAttackPlayer(s, player.id, target.id)) throw new Error('该玩家当前不可攻击');
  if (this.teamHasOutpost(target.id)) throw new Error('目标受前哨保护，需先摧毁前哨');
}
```

即使旧版前端、过期快照或手写请求把非法目标送进来，也无法落盘。

### 2. 界面：直接告诉你「服务端在跑旧代码」

服务端启动时记下时间戳，之后每次请求对比源码 mtime；发现文件比进程新，就在响应里带 `codeStale`，界面顶部弹出紫色提示条：

> **服务端在跑旧代码**　`src/engine/modes.js` 在该服务启动（2026/11/8 20:41:30）之后被修改
> 关闭该 node 进程后重新运行 start-server.bat；否则对局仍按改动前的规则判定

### 3. 测试：把这个座位布局钉死

`test/emperor-targeting.test.js` 覆盖：

- 三种大将轮换（0/1、2/3、4/5）下，每名提督的可攻击目标**恰好只有对位**
- 大将可打全部敌方玩家，且打不到队友
- 5 号提督在对位 4 号存活时打 0 号大将 → `applyAction` 与 `attack()` 双层拒绝，且不扣权威
- 对位阵亡后解锁：目标恰好多出敌方大将，仍不能打另一名提督
- 战斗值不足 / 伤害为 0 / 打自己 → 分别抛错且不消耗战斗值

## 六、以后怎么避免

1. **改完代码必须重启服务**。Node 不会热加载；`start-server.bat` 检测到 4397 已占用时会直接打开旧服务，不会重启它——所以要先关掉那个 node 窗口。
2. **看到紫色提示条就是旧进程**。它只在源码比进程新时出现，出现即代表当前对局不可信。
3. 判断进程新旧，不用猜：

```bash
node -e "console.log(new Date(require('fs').statSync('src/engine/modes.js').mtime).toLocaleString())"
# 与任务管理器里 node.exe 的启动时间对比
```
